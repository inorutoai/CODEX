# 日常の使い方：URLを開くだけ

おすすめは、アプリを常時利用できるサーバーへ配置し、固定URLから使う方法です。初回設定が済めば、普段はチャット・ターミナル・Dockerの操作は不要です。

現在は開発環境での動作確認まで完了しています。利用者向けの固定URLはまだ発行していません。

## 普段の操作

1. ブックマークしたアプリのURLを開く。
2. 自分のアカウントでログインする。
3. サイトと確認事項を登録し、改善が終わったら「解決済み」にする。

スマートフォンは同じURLをホーム画面へのショートカットとして追加できます。オフラインアプリではないため、インターネット接続が必要です。

データはログインした本人の管理領域に保存されます。現在は他のメンバーと共有する機能はありません。患者情報やパスワードは入力しないでください。

## 担当者が一度だけ行う設定

VercelにNext.jsアプリ、Supabaseに認証とデータベースを配置する構成を想定しています。両サービスは本人・組織のアカウントを使い、用途に合うプランを選んでください。

1. **本番データベースを用意する。** Supabaseでプロジェクトを作成し、[スキーマSQL](../supabase/migrations/20261026000000_security.sql)を適用します。
2. **アプリを配置する。** Vercelでリポジトリを読み込みます。アプリを収録した `codex/security-console` ブランチをデプロイ対象にし、Root Directoryは `security-app` にします。現時点では `main` にアプリはありません。フレームワークとインストール・ビルドコマンドは同梱の `vercel.json`、Node.js 24は `package.json` で指定済みです。
3. **保存先とログインを接続する。** Vercelの環境設定に `NEXT_PUBLIC_SUPABASE_URL` と `NEXT_PUBLIC_SUPABASE_ANON_KEY` を登録してデプロイします。Supabaseの認証設定では、発行された固定URLをSite URLにし、そのURLの `/auth/callback` を許可します。メール確認・配信も設定します。公開キーを使用し、service_roleキー・DBパスワードをアプリへ渡さないでください。
4. **動作を確認して利用者へ渡す。** 本番の2アカウントで保存と相互アクセス拒否、メール確認を検証します。承認済みロゴを配置してから、固定URLと簡単な操作案内を利用者へ渡します。

詳しい管理者向け手順は [README](../README.md#公開用supabaseプロジェクトの作成接続) にあります。キーやパスワードをチャットへ貼る必要はありません。

開発環境の「Publish」は開発環境を保存する操作です。利用者向けアプリの公開や、Supabaseプロジェクト作成とは別です。公開後の日常利用では、開発環境の起動やPublishを繰り返す必要はありません。
